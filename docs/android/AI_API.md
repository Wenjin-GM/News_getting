# 原生 Android 可选 AI 调用与本地数据

实现依据：4.2.1-dev（40201），2026-11-13。AI默认关闭；基本采集、收藏和已读不依赖API。启用后使用用户测试并保存的模型，失败不自动换模型；不要通过聊天或报告提供真实Key。

## 通用接口与设置

设置页AI功能与外观/缓存管理并列成卡片，提供“接口与模型 / 与AI对话”两个入口；未启用时聊天入口禁用。4.2.1拆成独立配置表单和聊天窗口，配置没有AI功能大标题或页签。输入公开HTTPS基础地址、Key和模型ID，不按厂商白名单限制；没有GLM/DeepSeek快捷按钮和品牌解释段落。保留自定义路径及有效HTTPS端口，拒绝私网/本地地址、URL凭据、查询参数和重定向，正常验证证书，不接收自签名放行。

使用标准Bearer鉴权、`GET /models`与`POST /chat/completions`。模型列表最多500个候选，不自动选第一个；服务不提供列表时手填ID测试，不再捏造品牌候选清单。测试所选模型成功后才能保存；未改变URL/Key/model的保存保留profile，避免误清缓存。要求服务返回兼容的JSON文本结果，模型ID若与锁定值不一致仍拒绝；非标准鉴权/协议或模型特有参数不能据“兼容”二字保证可用。

已知官方DeepSeek使用原有非思考参数，结构化任务附JSON输出参数，其他兼容地址不擅加这些专用参数。依据：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[并发与排队说明](https://api-docs.deepseek.com/quick_start/rate_limit/)。JSON模式不能替代引用与非空校验，也不能保证事实正确。

## 更新与标题翻译

1. 一键获取已启用来源，失败保留原快照；linux.do仍独立更新。
2. 优先翻译当前列表中未缓存的纯外文标题。翻页或切到其他列表时按需补译，不为所有未显示条目一次性付费；搜索输入中暂停自动补译。标题阶段显示“正在翻译标题”，每批最多48个、同时保留字符边界，已完成批次即时显示与保存。
3. 新闻最新、新闻分站热榜、AI平台动态分别生成汇报；每个分区结束立即更新其卡片内部，不等精选、不反复重建筛选顶栏。
4. 汇报阶段全部结束后，生成新闻与AI两分区**当天**精选。同阶段最多两路，保留阶段屏障。

汇报仍对成功快照（含沿用缓存）的全部相关标题分批分析，不受UI搜索/筛选/分页限制。每批最多96标题/约16000字符；分批汇报360 tokens、合并650，精选提示最多8组/40字理由、1800 tokens（兼容校验最多12组）。精选可推荐单篇。只传临时ID和标题，无正文/链接/热度；输出ID必须映射本批本地文章，重复首次认领，未知引用限一次同模型纠错。

外文列表只替换显示标签，缓存按原Article ID+原标题匹配，保留来源/时间、ID、原文和分类。中文译名也可搜索；详情标题、正文仍显示原文。未启用AI时显示原文；缓存未命中时显示翻译中，失败保留原文，不伪造中文。语言识别为Unicode启发式，不能保证区分所有仅汉字的外文。

4.2更新时搜索先停止输入，再以320ms收窄/淡出，最终GONE、动态按钮填满栏内宽度；依次显示“正在…”与旋转图标，结束逆向恢复。相同工作状态切AI阶段不重新伸缩，动效可关且尊重系统动画开关，进度线占位不让列表跳动；动画不修改阶段计数或请求时序。搜索只在触摸时激活；收键盘、点其他位置、切后台均清焦点/光标，返回不主动打开。API30+监听IME Insets，API26–29有可见区域兜底，另处理Back预输入事件；不同厂商输入法仍需真机复验。

## 按内容日期保存精选

- 日期一律按文章`published`转上海日期；不能用`fetched`或本机获取日替代。当天输入限定 `[当天, 次日)`，不再默认反复选择近7天。
- 每分区默认显示今天及前两天中已存的精选；昨天/前天未选过则不自动生成，也不伪造空日期报道。今天没有结果时保留刷新入口。
- 每按一次“更早的本地AI精选”向前扩展三个日历日，分别判断：已选结果直接显示；缺结果时复用归档、来源快照（含失败时保留的旧条目）及已存精选内的有效原文，不从收藏倒填、不改写归档的获取历史。只选择本板块、已启用来源和实际published日期的报道。
- 优先完成本地日期的整理，再逐日处理仍缺内容的日期，不能因三天中一天为空就阻塞其余两天或重选它们。只复查相关来源；现有非分页列表的最早日期晚于目标日时，不再抓最新列表冒充补历史。显式单日刷新可重新检查，不受普通历史复用限制。
- 已检查且没有目标日内容，以独立的historyChecks元数据保存，重启不反复无效获取；以后本地出现可用报道时优先重新整理，单日刷新图标可主动重查。来源全失败或部分失败且仍无输入，不写“确定无内容”，显示失败并保留旧结果。成功分析但模型选择空groups是另一种已选结果，同样持久化。
- 当前来源适配器没有通用的按日期历史分页。列表未返回目标日就显示暂无可获取内容；不能拿今天的帖子当过去日期，也不承诺安装前历史。
- 每日标题行有独立刷新图标和展开/收起图标。刷新只重查相关来源并重选指定日；其他日期结果不变，失败保留旧精选。展开窗口/折叠状态目前在Activity内存中，重启回到默认三日窗口。
- 已选历史以`featured-news@YYYY-MM-DD`、`featured-ai@YYYY-MM-DD`为逻辑键。旧聚合精选按实际报道日期逐日补迁移，即使部分日期已迁移也补齐缺日，绝不覆盖已存日期；迁移会落盘。切换API/profile保留已按日保存的精选，并逐日标注原模型；新请求始终用当前锁定模型。

## 缓存关系与清理日历

主新闻状态仍`native-news-v3.json/schema3`；归档仍`news-archive-v1.json`（最多12000条/16MiB）。归档结构/记录先验证再恢复；读取失败时保留原文件与已知内存记录、显示错误并禁止覆盖，提供重试读取，不能静默当成空归档写回。

4.1.1的AI结果由`AiResultStore`保存：`ai-results-v1.json`是AtomicFile索引，含汇报/译名/批次/historyChecks和dailyFiles引用；按日精选写入`ai-day-<SHA256>.json`不可变内容文件。先完整写新文件，再原子替换索引，提交成功后仅清理不再引用的日文件。中途写失败仍读旧索引；清理后的旧文件不靠扫描自动恢复。旧单文件无dailyFiles的格式仍能读，迁移时改写为新存储。

索引最多6MiB、单日日文件最多6MiB、全部有效AI数据最多64MiB；不自动淘汰已选历史腾空间。达到上限/存储不足时明确未保存，可清缓存后重试保存。每日及汇报区分正在保存、已保存、未保存；只在AtomicFile索引提交成功后标已保存，不把内存结果当成功落盘。读取失败的AI文件受写保护，自动分析暂停；重试读取成功后恢复，显式清除AI配置才一并删除其结果/日文件。新增字段皆可选，旧文件缺字段仍可读取；不是无限存储。

`AiTitles`最多1500项/约1MiB；成功批次缓存最多96项/384KiB/7天，存哈希与输出，不存请求体或Key。批次按profile/URL/模型/提示版本/预算/输入匹配；未知引用响应移出缓存，命中仍校验当前引用。保留旧的121标题汇报4次降3次、重复输入0新调用的合成证据，不据此承诺真实耗时。

设置“清理缓存”打开月份日历：带•的日期表示存在任意内容缓存，包括原始条目、快照、译名及已选结果（含空groups），不代表新闻精选一定已生成。可多选日期清除，也可选一个截止日清除严格早于它的日期（不含截止日），执行前有确认。**11月12日取得的11月10日文章属于11月10日。**无发布时间的条目不按获取日归类。只有“未获取到内容”的检查元数据不算内容缓存。

清理联动：归档、普通/热榜快照、linux.do三子页、对应日期精选/historyChecks、译名及相关汇报；通用AI批次缓存和进程内全文缓存失效，避免残留派生内容。删除后重排队的旧AI写入受generation/revision拦截；日历清理在更新/配置读写期间禁止，读取失败有待保护的文件时先要求重试读取，不能虚报已清理。

收藏（含其保存的原文副本）、已读、来源开关、主题和API配置明确保留。清理不存在内容的日期不会清空其他缓存；以后主动刷新或阅读保留收藏可能重新生成相关缓存，这不是从未抓到过的历史倒填。

## 详情翻译与对话

外文预览按钮有边框，状态为“翻译 → 正在翻译…（禁用）→ 取消翻译”；取消隐藏译文，原文始终保留。只在点击后发送当前预览内容，不自动取更多正文；失败回到可重试状态。

独立对话窗使用已保存并启用的配置，不使用未保存的URL/Key草稿，不切换模型。仅手动发送当前会话消息，不自动附带新闻。上下文最多最近12轮，输入有长度限制；清空/关闭窗口丢弃会话，未做聊天记录持久化。左右气泡不加“你”前缀；记录区单独滚动，固定输入/清空/发送区随IME避让，回复期间不禁用输入，发送后不抢焦点。清空也清草稿；迟到回复不覆盖已清空/关闭窗口或已换配置的会话，已发出的API请求不能承诺撤回计费。

URL/Key/model/profile仍AndroidKeyStore AES-GCM私有密文保存，不进入新闻状态、聊天上下文、日志或分享APK。新闻/精选/译名是私有普通缓存，并非密钥库。停止AI不影响基本新闻；“清除AI配置”则按确认提示同时删除AI结果/译名缓存。

## 失败与验证

HTTP401/402/403/404/429阻止后续新请求，最多另一路已在途。普通网络错误不盲目自动多次重试，分区可单独重试。区分连接超时、读取等待、DNS、TLS、连接断开和兼容响应结构；不回显原始服务体、Authorization或异常中的秘密。连接10秒/读取60秒以及响应流原90秒截止检查未放宽。

- `python scripts/android/test.py`：解析/身份/全标题/缓存，译名/内容日/通用接口，以及HistoryStorageTest的分日计划、本地快照复用、部分迁移、超过6MiB重载、原子提交故障和损坏读保护。
- `build.py`与`build-smoke.py --ui/--ai/--reader`：产品及独立测试包，不把测试类放进产品。
- `ReaderFeatureSmoke`：中文标题/搜索、手动译文状态、满栏更新、焦点释放/后台返回、当日精选/三日前翻/单日图标、空历史、日历实际点选确认、清理联动、历史重启/换配置保留、标准接口设置和锁定对话。
- `build-smoke.py --history`：HistorySmoke在旧4.1.0种入部分迁移单文件及空结果，覆盖升级后检查迁移落盘；真实Android AtomicFile/Keystore下验证超过6MiB、容量失败/重试、读取损坏保护与清理重启。接口合成，不消耗真实API。
- `build-smoke.py --chat`：ChatKeyboardSmoke用真实IME及触摸验证无需收键盘的发送/清空、按钮可见/间距、多行输入、原文气泡、焦点及清空后的迟到回复；旧版系统/厂商输入法仍需真机。

真实API成本/译文质量、所有厂商/机型/输入法与来源历史可达性未全验证。实际包、测试结果、风险见[HANDOFF](../../HANDOFF.md)；来源事实由[SOURCES](SOURCES.md)维护，静态模型资料日期未改。
