- 主产品仍是原生 Android 独立 APK。安装并联网即可用，可转发给他人，不依赖作者账号、电脑在线或自建后端。
- 基本功能是三块并列内容：按时间排列的最新流、按来源分榜的热度、整理后的离线 AI 情报。
- 用户自备 API Key 不进入基本功能。端侧模型只在第 5 步做实验，通过前不写进应用。

- 情报资料收成一份规范化 JSON：保留现有 `providers` / `tools`，再增加模型、分析、事件、证据和缺口。工具事实只保留一份。网页以后从该 JSON 派生。APK 不承诺每周自动刷新，快照随新版本更新。
- 测试包只输出到 `dist/android/`。不替换 `releases/android/`，不提交、不推送。
- 已有未提交内容保持不动：`AGENTS.md`、`HANDOFF.md`、`MEMORY_PROTOCOL.md`、`memory/`、`scripts/check-handoff.py`、`AI情报站/`，以及 README 与若干文档里指向交接入口的说明。

## 无模型精选 · 真机验收通过

本轮不用模型，也不使用 API Key。不导入情报站，不新增来源，不替换正式包。测试包使用 `versionCode=30300`、`versionName=3.3.0-dev`。保留界面一轮已经做成的顶栏、详情里的收藏／分享／原文，以及失败保留旧快照。

名称定为：底栏「今日」改为「新闻」；「最新」保留；「热度」改为「分站热榜」；新增「精选」。分站热榜表示各站自己的榜，数字仍不跨站相加。精选是多家来源对照，不是编辑评分。

### 1. 三个视图

新闻页有「最新」「分站热榜」「精选」。

- 最新：按发布时间排列，范围是现有综合、科技、财经新闻源。不包含 `v2ex`、`v2ex-latest`、`hackernews`。
- 分站热榜：只保留今日头条和百度贴吧，各榜仍按 `rank`。其中命中现有 AI／科技规则的条目不在这里显示。
- V2EX 与 Hacker News 只出现在 AI 专栏的热度里，而且必须命中 AI／科技规则。Hacker News 整榜按科技处理。V2EX 里对不上规则的帖，新闻和 AI 专栏都不显示。

### 2. 列表补充来源和时间

新闻、分站热榜、精选、AI 专栏和收藏的预览都显示标题，标题下用小字写来源和发布时间。没有发布时间时写「未提供」，不能写成 0。点开后的详情保持现有摘要、收藏、分享和原文。

精选的一条代表一个事件：小字写「N 家来源」和该事件最近一篇的时间。

### 3. 精选用规则归并

只使用本机已经抓到的新闻条目。标题归一后，文字重合达到阈值，并且发布时间相距不超过 72 小时，视为同一事件。同一来源的重复链接只留一篇。至少两家不同来源才进入精选。单独一家的报道留在最新里。

事件按最近一篇报道的上海日期分组，新的一天在前。页面先展示本地保存的近 7 天。用户可以继续往前翻更早的本地记录。

事件页列出各家的标题、来源、时间和摘要，并各自打开原文。不生成综述，不计算跨站热度指数，页面标明这是本机已抓来源的归并。

### 4. 历史从安装后开始积累

现有快照每次刷新只保留来源返回的最新一批，不足以回溯一周。本轮追加一份有容量上限的本地归档，刷新时并入新条目，至少保留 7 天，更早的记录在不超过上限时继续留着。文章 ID 算法不变。旧收藏、已读和来源开关必须还能读。

刚安装或刚升级时，只能看到各来源这次返回的内容，不能显示并未抓到的更早日期。来源接口没有更早分页时，翻到底就停止，并说明本地没有更早记录。不为了补历史关闭 TLS 或抓取正文。

验收：

- 新闻页能在最新、分站热榜、精选之间切换。V2EX 和 Hacker News 不出现在新闻页。
- 同一事件的多家报道在精选里只占一条，事件页能看到各家标题。两件只是提到同一公司的新闻不会仅因公司名被并在一起。
- 列表能按日期看到本地近 7 天的精选；没有归档的日期不编造条目。
- 预览含来源和发布时间。
- JVM 测试覆盖归并、7 天分组、旧状态兼容，以及单来源报道不进入精选。
- 测试包只进 `dist/android/`。用户已于 2026-11-09 完成真机验收。

## 真机修正

针对 `3.4.0-dev` 的试用结果。测试包改为 `versionCode=30500`、`versionName=3.5.0-dev`，仍只输出到 `dist/android/`。不改正式包，不把模型资料日期改成今天。

### 1. 「全部」和其他分类互相取消

新闻分类仍是多选，但「全部」和具体分类不能同时处于选中状态。点具体分类时取消「全部」；点「全部」时取消已选分类。点具体分类之后，仍可以继续多选其他具体分类。

当前 `ReadingRules.choose` 在「全部」被程序取消勾选时会清空整个集合，对话框里就会出现「全部」和具体分类同时亮着。修正时避免这次递归把刚选中的分类清掉，并用测试锁住最终集合。

### 2. 精选改为向下展开日期

去掉新闻精选和 AI 精选上的日期选择器。页面按上海日期从新到旧排列，每个日期可以单独收起和展开，默认展开最近的日期。滑到末尾继续查看更早的日期。

本地没有更早日期时，当场刷新相关来源，把返回结果里属于缺口日期的条目归并进去。刷新仍使用现有公开接口。这些接口通常只返回最新一批，不能按任意历史日期取回当天内容。刷新后仍没有该日条目时，说明「来源没有返回这一天」，不编造，也不再只在本地档案里静默查找。

### 3. 平台动态只留模型和厂商消息

平台动态不显示工具版本更新。凡是工具条目的 `sourceId` 指向的来源都排除，包括 Kimi Code、Codex、Claude Code、Gemini CLI、Qwen Code 等发布流。

厂商新闻、模型更新日志里的新模型发布继续显示。工具页仍展示那些被排除的版本更新。

### 4. 模型预览缩短并排序

模型列表每一项只显示模型名、厂商、发布日期和特点。优势、劣势、分析和出处放进点击后的详情。列表按发布日期从新到旧排列，没有日期的放在最后。

### 5. 模型资料日期保持 2026-10-21

`2026-10-21` 是导入的情报快照日期，不是漏改的字面量。每天打开应用可以再检查已有官方动态，并在模型页显示「最近检查」时间。检查成功不能把快照日期改成今天，也不能把旧的优势、劣势标成今天已核实。

官方动态里出现快照中没有的新模型时，可以在模型页单独标出「新发布，尚未写入资料」。没有每日人工或模型复核之前，不自动改写特点、优势和劣势。

验收：

- 选「新闻」后「全部」熄灭；再点「全部」后只剩「全部」。具体分类之间可以同时选中。
- 精选没有日期选择器。日期可以折叠，向下可以走到更早日期；缺记录时能看到一次刷新的结果或「来源没有返回这一天」。
- 平台动态不出现 Kimi Code 这类工具版本，仍出现模型发布新闻。
- 模型预览只有名称、厂商、发布日期和特点，顺序按发布日期。
- 模型页同时能看到资料日期 `2026-10-21` 和最近检查时间，两者不会被写成同一个「今天已核实」。
- JVM 测试覆盖分类互斥、工具来源排除和新模型不改写旧快照。手机验收由用户完成。

## 4. 逐源扩充

一个来源验证通过再加入下一个。失败时隔离、冷却并保留旧缓存。未文档化的站内接口默认关闭。

1. 掘金热榜。2026-11-09 开发机探测返回 50 条，含标题、内容 ID、浏览、点赞、收藏、评论。第一条的 `hot_rank` 为 1197，不能先把它当成名次。还需要确认字段含义，并在手机网络、多时段复测。
2. 人民日报当日电子报目录，只收版面标题和文章链接。它是日报内容，不标成实时热榜。
3. 已验证的厂商栏目或官方 RSS，按产品逐家加入。本轮见过成功响应的例子包括 AWS 机器学习博客和 Microsoft Semantic Kernel 博客。不承诺厂商首页全覆盖。
4. 新华社继续寻找官方栏目列表。旧 `rss.htm` 返回 404，不能据此断言所有渠道都不存在，也不能在未验证时接入。

linux.do 的 `/latest.json` 本轮返回 403。微博现有 JSON 端点返回 403。X 的官方趋势接口需要开发者账号和 Bearer Token。三者都维持关闭。

验收：每个新来源都有成功与失败 fixture。失败不清空已有条目。手机网络结果由用户确认。

## 5. 热点整理实验

在第 1 步和第 4 步取得的真实标题上进行比较，再决定是否加入端侧能力。

- 热不热：继续用榜单、浏览、点赞、回复及其增长，保留可解释的数据。
- 是否同一事件：先做规则去重，再与端侧文本向量聚类比较误合并率、包体、耗电和延迟。
- 发生了什么、有哪些观点：模型输出必须链回输入材料。不能凭标题补浏览量，也不能把语义相似写成「全网都在讨论」。只有标题和短摘要时，限制事件原因分析。

验收：比较记录足够决定做或不做。未通过前不改变默认阅读路径。
