# 技术决策、原因与取舍

增量核实：2026-11-09。用户需求依据当前会话的人类消息与明确授权的 TODO；实现依据源码。优先级和状态按根 [MEMORY_PROTOCOL](../MEMORY_PROTOCOL.md)；本文件拥有决策原因，硬规则执行入口为 [AGENTS](../AGENTS.md)。

## D01 · P0 / Active · 手机必须真正独立

**用户确认**：Android 手机，必须有可下载并转发给他人的 APK；收件人安装、联网后直接使用；新闻获取与展示均由应用完成，不依赖 GPT 云平台、作者账号、电脑在线或自建聚合后端。

**选择与原因**：3.0 改为 Java 原生 UI、手机 HTTPS 采集/解析、内置来源和 AI 目录、私有缓存。PWA 可安装、网页壳可出 APK，但此前的远程站点与云采集依赖仍违背最终要求。当前没有 WebView 或后端是源码事实，见 [architecture](architecture.md)。

**取舍**：实时新闻仍依赖互联网与来源网站；“独立”不是离线生成新闻。完整媒体原文可选外部浏览器，默认应用内阅读来源标题/摘要。没有承诺绕过登录、验证码、付费墙或抓取所有全文。

## D02 · P1 / Active · 两端保留，运行分离

最初用户允许电脑部署后手机访问；后续手机独立要求取代该前提。保留已完成的 Go/Windows 版作为附加产品，避免丢失桌面能力；它不是 APK 后端。双方共享目录资料而不是共享在线服务。

## D03 · P0 / Active · 用可观察降级提高稳定性

**用户目标**：一键获取时尽可能稳定取得各类新闻，程序轻量、不要庞大后端。

**已实施选择**：来源隔离、同平台备用、超时与大小限制、私有快照、失败保留旧内容并显示错误/历史标记。官方/公开渠道优先，无共享登录 Cookie 或作者密钥。

**原因与边界**：第三方结构、网络与限流不受应用控制，不能保证全源永久成功；不以关闭 TLS、安全校验或伪造成功达标。默认关闭实验源不算默认渠道成功的分母。参数契约见 contracts。

## D04 · P1 / Active · AI 专栏有资料语义，不只是新闻标签

**用户确认**：专设 AI 栏，获取各平台动态，整理厂商出品的 AI 编程软件和 Harness。

**已实施选择**：同时提供官方动态、标注来源的媒体补充、工具目录类型筛选与模型资料/对比；旧的工具许可对比已被模型对比替代。目录是内置快照，不因每日抓取动态而自动重新核实。单一维护源由 architecture 指定，不能三处各写一份。

**语义取舍**：产品/IDE/CLI 是使用入口；Harness 负责智能体任务循环、工具与权限；SDK 提供集成；通用 framework 不等于完整编程产品；模型/API/Coding Plan 不自动成为 Harness。开源、免费与托管依赖分开判断，字段解释见 contracts。

## D05 · P0 / Active · 权限与内容执行面保持克制

**用户确认**：限制应用访问本地机器内容，做好恶意内容/病毒风险防护。

**已实施选择**：仅 INTERNET 权限、原生文本展示、私有状态、标准 HTTPS 与受限 URL、精确只读 APK 分享，不请求全盘存储权限，不执行新闻脚本或动态代码。

**原因与取舍**：直接分享可用安装包不需要任意本机文件服务；安全由多层限制支撑，签名用于身份和完整性，不等于“绝对无病毒”或第三方审计。精确契约由 contracts 维护。

## D06 · P1 / Active · 正式发布身份与本机重建分离

`releases/android/` 保留已经交付的文件；日常重建到 `dist/android/`。同版 ZIP 时间戳等可改变 APK 哈希，不能自动覆盖发布包。覆盖升级依赖原签名，不能通过重新生成密钥修复官方升级。身份真值与路径见 contracts/conventions。

## D07 · P2 / Active · 采用工作空间内便携工具链

**已接受实现，而非用户指定必须使用 Java/Go**：原生 Java + Python 标准库脚本 + 固定官方便携 JDK/SDK；Windows 版 Go + 内嵌静态页面。原因是控制体积和开发依赖、保持所有本地写入在工作空间。APK 无需 Gradle、Node、Python 或开发机服务才能运行；当前构建脚本仅验证过 Windows。

## D08 · P1 / Active · 整理与 Git 发布已完成，授权不自动延续

用户指定根仓库 `https://github.com/Wenjin-GM/News_getting.git` 并要求整理后上传；该阶段完成于 `f51c8e7`。旧源码恢复包、签名和个人数据留本地，源码按模块归类。

历史上传授权不自动延续；是否有当次提交/推送授权以用户最新指令及 HANDOFF 为准，不能延伸为公开私有细节或删除云资源。

## D09 · P2 / Active · 协作偏好与明确边界

- 用户倾向中文、直接执行、交付相对完善可运行成果；已确认信息不重复询问，长任务提供有效进度。
- 森林绿/奶油底是已接受实现，不是用户声明不可变的审美硬规则。
- 不把一次“出门半小时”的安排当永久期限、定时任务或持续自动执行授权。
- 用户已提供部分真机通过与失败反馈，具体证据和当前待验收状态由 HANDOFF 维护；手机型号/Android 版本仍未记录。未要求账号、云同步、广告、遥测、自动更新或后台推送。
- 工作空间规则和最终披露本机状态由 AGENTS 统一维护。

## D10 · P1 / Pending · 尚未决定的长期事项

- 项目自身 LICENSE 未由用户选择；公开仓库与第三方许可不代表可替用户选择项目许可。
- 收藏备份/迁移、安卓自定义 RSS、后台推送、全文抽取、自动更新、云同步均未承诺；如新增应先以新需求确认边界。
- 历史云站点是否退役尚未授权处理，工作断点见 HANDOFF。

## D11 · P1 / Active · 最新、分站热榜与无模型精选分开

**用户确认并授权实施**：最新按时间；分站热榜保留站内列表顺序和原始热度，不做跨站加分；精选依据标题相似、72 小时窗口及多家来源交叉归并，不生成综述。来源范围与算法契约见 contracts C08。

**原因与边界**：是否同一事件与站内热度是两个问题，标题规则可先交付可解释切片。用户曾提议模型用于整理分析而非采集，但当前轮明确不用模型/API Key；未来端侧实验是候选，不是永久禁止或当前开发授权。不接入 aihot.news 等第三方聚合后端。

## D12 · P1 / Active · 内置资料与实时动态分别维护

**用户确认并授权实施**：情报资料采用内置结构化快照与原生展示；动态继续来自已有官方列表，不内嵌智能体、不以用户密钥作为基本功能。模型仅导入部分结构，不能宣称完整情报站已完成。

**最新覆盖指令**：移除模型列表和详情的“模型资料日期”文案，但不改底层资料日期或内容。显示最近检查成功，只表示取得动态，不能把旧分析改称今天已核实。确有新发布线索可单独提示，不自动补写特点/优劣势；具体日期和置信度契约由 contracts C06 维护。

Go 本地新闻台 1.0 → AI 升级 1.1 → PWA/Sites 私有站点 → 按分享要求公开站点和 WebView 2.1 → 用户明确独立性 → 原生 3.0。

PWA 的所有者门页、依赖 GPT/云采集的部署和网页壳均已被 D01 替代；仅保留这段原因，不保留失效部署步骤。旧站点本地源码删除不等于外部资源已下线。
